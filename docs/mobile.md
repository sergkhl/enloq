# The Enloq app

The Mobile Client of [ADR 38](adr/0038-mobile-expo-client.md) lives in
`mobile/`: an Expo SDK 57 app (React Native 0.86, Expo Router, strict
TypeScript) for iPhone and Android, named Enloq with the ID
`com.globesoul.enloq` and the link scheme `enloq`. Its backend is the service
on the VPS at `https://enloq.globesoul.com`; automated checks use the authored
fixture server instead. The app imports the web's pure rules (routes, times,
Reply Quotes, author lines, Message Runs, the Unread line, the Media Carousel,
group reading and more) from `shared/`, which `mobile/metro.config.js` adds to
Metro's watched folders. The app is the target platform: the rebuilt web
follows its screens ([ADR 44](adr/0044-mobile-only-web-in-the-apps-design.md)).

## Builds

iOS builds run on the Mac checkout `~/_DEV/enloq`, since Xcode needs macOS:
Xcode with the iOS simulator runtime and CocoaPods. Android builds run there
too (the Android SDK with JDK 17) and on the VPS checkout
`~/pi-workspace/enloq` ([below](#android-builds-on-the-vps)); Saved Builds are
made on the VPS only. CocoaPods needs a UTF-8 locale, so build commands set
`LANG` and `LC_ALL`. The `ios/` and `android/` folders are generated by Expo's
prebuild on demand and never committed. There is no Expo account, EAS build or
over-the-air update, and every command runs with `EXPO_NO_TELEMETRY=1`.

```sh
npm --prefix mobile ci
cd mobile
npm start                                      # Metro for development builds
npx expo run:ios --device "<simulator name>"   # development build, simulator
npx expo run:android --device <model>          # development build, Android
```

`npm start`, `npm run ios` and `npm run android` set the telemetry switch
themselves; a bare `npx expo` command needs `EXPO_NO_TELEMETRY=1` exported
first. On Android a development build installs as **Enloq Dev**
(`com.globesoul.enloq.dev`), beside the release build: the debug build type
adds the `.dev` suffix and its own label (`mobile/app.config.ts`), so fixture
journeys never touch a phone's real pairing. A development build loads its
JavaScript from Metro, so the device must reach the machine running it: an
Android phone over USB does with `adb reverse tcp:8081 tcp:8081`. An Android
model name is the one `adb devices -l` prints after `model:` (the Galaxy S9+
is `SM_G965F`). A development build needs rebuilding after a native module is
added, but not after JavaScript edits. If Android's **Appear on top** setting
opens on a first launch, leave it off and go back.

After `npx expo prebuild --clean` Gradle finds the SDK only through
`ANDROID_HOME`, with `JAVA_HOME` set to Java 17; `mobile/scripts/android-env`
sets both on either machine (on the Mac `~/Library/Android/sdk` and
`/usr/libexec/java_home -v 17`). `expo run:android` installs Enloq Dev but then
looks for the release ID to open it, so open it by its development link:

```sh
adb shell am start -a android.intent.action.VIEW -d 'exp+enloq://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8081' com.globesoul.enloq.dev
```

A simulator build that quits at launch with `Library not loaded:
@rpath/ReactNativeDependencies.framework` has a Pods folder that mixes React
Native's prebuilt core with dependencies built from source, as a pod install
over an earlier one can leave it. Regenerate the project with
`npx expo prebuild --clean --platform ios`, which reinstalls the pods, and
build again.

Metro watches source files only when `CI` is unset: with `CI=1` it keeps
serving the code it found at startup, so a development build shows old code
after every edit. Start it with `npm start` from a shell without `CI`.

### The iPhone without the Apple Developer Program

iPhone builds are signed by the owner's free Personal Team. Each install stops
launching seven days after it is signed, the phone needs **Developer Mode**
(Settings → Privacy & Security), and the first install needs the developer
approved under Settings → General → VPN & Device Management. Free signing
cannot receive push notifications, so iPhone push waits for enrollment.

For everyday use the iPhone gets a Release build with its JavaScript embedded,
so it runs without the Mac. With the iPhone connected and unlocked:

```sh
mobile/scripts/install-iphone
```

The script takes the Personal Team from Xcode's accounts and the first paired
iPhone from `devicectl`, then builds and installs. Run it at least weekly. The
team ID reaches the build through `ENLOQ_APPLE_TEAM_ID` (`mobile/app.config.ts`)
and is never committed. Installing over the existing app keeps its Keychain
entry, so the phone stays paired.

### The Android phone

The Android phone's everyday build is a release build with its JavaScript
embedded, so it runs without a development machine and never expires. With USB
debugging on and the phone connected, or from the VPS over the tunnel:

```sh
mobile/scripts/install-android
```

It builds native code for the connected phone's processor only, installs and
starts the release app. Enloq Dev is a separate app with its own pairing and
never replaces it.

The Galaxy S9+ is restricted to Maya's test account or the authored
development login, in both Enloq and Telegram (ADR 38 Q31, Q36). Never sign in
to the Owner Account or pair the phone to the owner's member: that pairing
grants access to the Owner Account even when Maya is selected. Revoke any
existing owner-linked entry in Trusted browsers and devices and clear the
release app's local data before tests. This leaves the service's Telegram
sessions and other clients intact.

**Signing.** Release builds, Saved Builds included, are signed with Enloq's
private release key (ADR 43 Q5), so only its holder can make an APK that
Android accepts as an update to Enloq. Any release build installs over the
previous one and keeps its pairing, and every Saved Build keeps version code
1, so any kept APK installs over any other. Enloq Dev keeps React Native's
public debug key.

The key lives on the VPS in `~/pi-workspace/enloq-service/android-signing/`
(mode 700): `release.p12`, a PKCS12 keystore holding the RSA 4096 key
`enloq-release`, valid until 2054, and `release.properties` with its alias and
password, both mode 600. It sits outside both checkouts, so a fresh clone
never loses it, and outside `secrets/`, so the service container never sees
it. Never print, commit or copy it into a checkout; the owner keeps its
backup. Losing it means every phone uninstalls Enloq and pairs again. A build
elsewhere, such as `install-android` on the Mac, needs a copy of that folder
named by `ENLOQ_ANDROID_SIGNING_DIR`. `mobile/app.config.ts` writes the
signing into every regenerated `mobile/android`; a release build without the
key fails rather than falling back to the debug key.

The certificate's SHA-256 fingerprint is
`6C:B4:D0:CC:79:93:7A:00:95:55:FE:33:27:F8:25:41:66:96:AD:23:D5:DA:8A:07:1C:F6:B5:72:C5:61:14:B1`;
`apksigner verify --print-certs <apk>` (in the SDK's `build-tools/36.0.0`)
shows an APK's. An Enloq signed with the earlier debug key refuses an update
signed with this one: uninstall it once, install the Saved Build and pair
again.

### Android builds on the VPS

The VPS checkout `~/pi-workspace/enloq` builds Android natively with the same
scripts: Java 17 (Temurin) in `~/Android/jdk-17`, the SDK in `~/Android/Sdk`
(platform 36, build-tools 36.0.0, NDK 27.1, CMake 3.22.1) and Maestro 2.6.1 in
`~/.maestro`, none of it needing root. `mobile/scripts/android-env` finds them;
on the VPS builds run at low priority, and Gradle keeps to four workers and
stops its daemon after ten idle minutes (`~/.gradle/gradle.properties`), since
the box is shared. Run the scripts through a login shell
(`ssh lrnki-vps 'bash -lc "…"'`), which puts `uv` and Node on the path.

The VPS reaches the development phone, the Galaxy S9+, over the wg-easy
tunnel: the VPS host is one client, mighty03
([operations](operations.md#the-vpss-wireguard-client)), and the phone another,
mighty02 at 10.8.0.3 in its WireGuard app, carrying only VPN traffic with a
25-second keepalive. A wg-easy client can be live on one device only. Android
10 has no wireless debugging, so network adb is switched on over USB from the
Mac, and on the rooted phone `phone-adb boot` makes it, and the tunnel, come
back by themselves after every restart (below). The first connect from the VPS
asks on the phone to **Allow USB debugging** for the VPS's adb key, where
**Always allow from this computer** remembers it. If the VPS still lists the
phone as `unauthorized` after that, connect again:

```sh
mobile/scripts/phone-adb network            # on the Mac, phone on USB
mobile/scripts/phone-adb connect 10.8.0.3   # on the VPS, the phone's tunnel address
mobile/scripts/phone-adb boot               # once, phone rooted, on USB or the tunnel
```

`connect` remembers the address in `.local/phone-tunnel-address` for later
connects. `phone-adb boot`, run once with Magisk's **Superuser access** set to
**Apps and ADB**, sets `persist.adb.tcp.port` to 5555, keeps WireGuard out of
Doze, turns off Android's Always-on VPN for WireGuard and installs a Magisk
boot script (`mobile/scripts/phone-boot.sh`). WireGuard restores the tunnel it
ran before the restart whenever its app starts, which the boot does through
its quick settings tile; the script starts WireGuard's VPN service if nothing
has, and notes what it found in `/data/local/tmp/enloq-boot.log`. A tunnel
switched off stays off. A start early in the boot fails if the server's name
doesn't resolve yet, and WireGuard then forgets the tunnel, so mighty02's
endpoint is the VPS's IP address and wg-easy's port rather than a hostname; if
the VPS's address changes, change the endpoint too. Android's Always-on VPN
is not used for the same reason.

Network adb then answers on the phone's Wi-Fi as well as the tunnel; a
computer the phone hasn't approved only gets the prompt. The WireGuard app
masks the tunnel's private and preshared keys in its editor: change other
fields without focusing those two or tapping **Generate new private key**,
never print or copy a key, and read its screens through UI dumps that drop
key-shaped text on the phone.

Then `mobile/scripts/install-android` and `mobile/scripts/journeys android`
work from the VPS checkout as on the Mac; adb's port reversal gives the phone
the VPS's Metro and fixture server. Enloq Dev installs from the VPS with
`adb install -r` of its built APK,
`mobile/android/app/build/outputs/apk/debug/app-debug.apk`. A debug APK of
about 100 MB takes minutes over the tunnel, against seconds over USB.
JavaScript edits need no reinstall.

### Saved Builds

A phone without the tunnel runs the release-type Enloq from a **Saved
Build**: an APK the service keeps in the Owner Account's own Saved Messages,
as one pinned message that each new build replaces (ADR 43, ADR 50). On the
VPS checkout `~/pi-workspace/enloq`, clean and committed:

```sh
mobile/scripts/publish-android            # build and post
mobile/scripts/publish-android --no-post  # build, show the caption, post nothing
```

The agent runs it after deploying any change to `mobile/`, `shared/` or the API
schema, and the owner can run it at any time. It refuses a checkout with
uncommitted changes, builds at low priority for arm64-v8a only, names the file
`enloq-<version>-<commit>.apk` and captions it with the version, commit, build
time in UTC and up to ten commit subjects since the last Saved Build. It hands
the APK to the service in `~/pi-workspace/enloq-service`, which takes it only
while `ENLOQ_OWNER_ACCOUNT` names a signed-in account
([operations](operations.md#saved-messages-of-the-owner-account)). The service
replaces the file and caption of its one Saved Build message in place, so the
message shows "edited" and keeps its place; the first build, or one after that
message was deleted, is posted anew and pinned once, silently. It deletes its
own copy once Telegram confirms the upload and never deletes anything in Saved
Messages; the script records the commit in `.local/saved-build` only then. The
foot of Settings shows `Enloq <version> · <commit> · <build date>`.

To install one, open Saved Messages in Telegram, tap the pinned bar at its top
to reach the Enloq APK, tap it and let Telegram install apps when Android
asks, or save it to Downloads and open it from Files, since Telegram's Play
Store build may not install APKs itself. If Samsung's Auto Blocker stops the
install, turn it off under Settings → Security and privacy → Auto Blocker. If
Android's developer verification refuses the APK (where it applies, and
everywhere from 2027), turn on Android's Advanced Flow once; adb installs stay
exempt.

## Pairing

The pairing screen's **Connect to enloq.globesoul.com** asks the server to post
a six-digit code to the Owner Account's Saved Messages, the six digits alone in
monospace so a tap in Telegram copies them; type it on the phone. A code lasts
two minutes and **Send a new code** posts another; five wrong codes end the
attempt, at most five code messages go out an hour, a phone has one attempt at
a time, and every refused code counts toward the server's refusal limit.
Saved Messages then records "<phone> was paired with enloq.globesoul.com". The
address is the build's release server (`ENLOQ_RELEASE_SERVER` in
`mobile/app.config.ts`, `https://enloq.globesoul.com` by default). The code's
last digit, typed or pasted, submits it, and Pair stays for a retry. Without an
Owner Account set, the server says so. Browsers pair with the same code.

**Sign in with Telegram** comes first on the pairing screen: enter a phone
number, the code Telegram sends (it too submits itself on its last digit when
Telegram gives its length) and the two-step password. The Owner Account, or a
member's first account, pairs the phone to them; a signed-out one signs back
in on the server, so this is the way back in with nothing trusted left.
Another account a member holds is refused. An account the server doesn't know
shows the **Member Agreement**; **Agree and ask to join** sends a Join Request
and the phone shows **Waiting for approval** with **Withdraw request**, asking
every five seconds until the owner decides in People: approval opens the
list, a decline or a week's expiry returns to pairing with a note. Connect
still asks for the owner's code, and says the Owner Account is signed out when
it is.

**Scan QR code** and the pasted link pair the other way: a trusted phone or
browser shows a QR code; scan it, check that both screens show the same
six-digit code, and choose Trust on the one that showed the QR code. The
server's terminal has no pairing command. Enloq Dev alone adds **Use the local
test server**: one tap pairs with the authored fixture at
`http://127.0.0.1:8776` through adb's port reversal, which approves its own
claim.

The app claims without cookies and keeps its credential in the Keychain or
Keystore. **Disconnect from <server>** at the foot of Settings, after a
confirmation, revokes that credential on the server, which ends its stream,
retires its push destination and cancels the logins it started; the phone
then forgets its FCM registration and offline copy and shows the pairing
screen. If the server can't be reached, the phone forgets locally and says the
server still lists it until it is forgotten there. Forgetting the phone in a
browser's or another phone's **Settings → Privacy** ends its access the same
way.

**Pair a phone**, in a trusted phone's or browser's Settings → Privacy, shows
a QR code with a two-minute countdown and **Copy link** for a phone without a
camera. On the new phone, **Scan QR code** (or the pasted link) shows a
six-digit code; the trusting screen then shows the phone's name and the same
code with **Trust** and Cancel. Leaving that screen cancels an unfinished
attempt. Only Enloq claims these codes: a browser that opens the link is told
to scan it in Enloq, and Saved Messages records every pairing.

## Accounts and trusted clients

The list header's account photo and name, with a chevron, open the account
sheet ([ADR 51](adr/0051-telegram-phone-look-and-new-messages.md)): it switches
accounts, opens **Manage accounts** and, as its last row after a divider,
**Settings**. It opens even without accounts, so Settings is always
reachable. **Trusted browsers and devices** is under Settings → Privacy, and
Disconnect and the build line are at the foot of Settings. Manage accounts
gives each account the web's actions by its state: Reconnect when it is signed
in but disconnected, Log out (Retry logout while one is pending), Sign in
again, and Remove local data for a signed-out account, each behind the web's
confirmation, plus its **AI processing** switch and **About you**. The service
keeps its guards, so unresolved sends block removal and spending records stay,
and removal also drops that account from the phone's offline copy. **Add
account** and Sign in again run the service's login flow: a QR code for
Telegram on another device to scan, or phone number, code and two-step
password with Resend. The code submits itself on its last digit when Telegram
gives its length. The login belongs to this phone, leaving the screen cancels
it, and codes and passwords are never kept on the phone. The empty list offers
Add account too.

Trusted browsers and devices lists each one with its kind and last access, this
phone marked, and **Forget** after a confirmation; forgetting this phone is
Disconnect.

## Offline reading

When the server can't be reached, the app keeps showing what it last loaded,
read-only, under a notice, also after a restart: the accounts, each account's
list, the 20 most recently opened conversations and the reading choice. The
copy lives in the app's cache folder, which iOS and Android leave out of
backups, ages out after 30 days and is deleted when the phone pairs again or
is forgotten. A conversation read from it acknowledges no viewing; the first
answer after an outage reopens the change stream, which rereads every screen.
Photos and avatars in the platform's own image cache are not part of the copy
and stay until the system evicts them or the app's data is cleared.
Replied-to messages that a conversation's Reply Quotes looked up are kept
beside its copy, under `replies:{account}/{peer}`, limited to the last 30 days
and deleted with the conversation's copy.

## The list and New Message

The list header holds the account switcher and the **Private | Groups |
Saved | Reminders** icons (a person, two people, a bookmark and a clock).
Private alone has the New Message pencil; its place stays empty on the other
tabs, so the icons never move. The first three tabs keep their account scope
and remembered choice; Reminders says All accounts and belongs to the member.
The app opens on Private.

New Message opens on the account's existing private chats, newest first,
older than seven days included, then the contacts it has never chatted with,
alphabetically. Typing filters both by name and @username and adds Telegram's
own people search under "Global search". It finds people only: no bots,
channels, groups or phone numbers. Choosing someone opens the chat, even with
no history, ready to write. A chat opened this way, from a group member's
profile or by a chat link shows its history as originals only and gets no AI
work; it joins the Private list once a message is sent or received there.

## Reminders

The fourth tab has a clock icon and says **All accounts** in its header
(ADR 58). Its first line, **Daily digest · 09:00**, opens a sheet for the
digest's time and timezone, initially 09:00 and the device's timezone; travel
changes no saved zone. Each reminder is a chat-like row: the person's photo
and name, the account with several accounts, the repeat ("Every Monday · 09:00
digest"), the Message Idea's first line or "Check in", and one date, when it
fell due or the next delivery. A pending row opens its chat and has a compact
**Dismiss**; an upcoming one opens the reminder editor, and the row's **⋯**
holds Edit. **Add reminder** chooses the account when there are several, then
the person with New Message's picker. Opening the list starts no AI.

The reminder editor is its own screen, opened from the tab, the Correspondent
Profile's Reminders section (the person's reminders and Add reminder) and the
Reminder Bar. Repeat is one compact choice: Once on a date, Every N days from
a first date, Every N weeks on a weekday from a start week, Monthly on a day
of the 1–31 grid, or Yearly on a month and day. Short months use their last
day and 29 February the 28th in other years, without moving later dates. The
alert is the Daily digest or an exact time from the phone's own time picker;
dates use its date picker. One row holds the timezone and the fallback
language, each chosen from a searchable list. The Message Idea is optional:
your words, [instructions] in square brackets, or both; an explicit date in it
("25 Oct", "25.10", "25 октября") keeps up to 20 of that day's cached messages,
and the editor says so ("Keeps 12 messages from 25 Oct"). The summary line
shows the next delivery before **Save reminder**; **Remove reminder** asks
first.

While a chat has pending reminders, the Reminder Bar above its suggestions
lists each by its idea's first line, or "Check-in reminder", with when it fell
due, its **Dismiss** and the way to its editor, and one set of suggestions
covers all of them. It is prepared two minutes before the alert and refreshed
30 quiet seconds after new messages; opening the chat prepares a fresh one only
when it no longer fits. Its options answer messages that arrived after a
reminder fell due. Nothing sends automatically. Without an idea, any message
you send after the due time completes a reminder, from any Telegram app; with
one, only a send whose draft took one of its options does, edited or not.
Dismiss completes either, and a Once reminder then ends. Either Automatic
suggestions switch pauses reminders, with future-only resumption; Account AI
Off permits alerts but blocks suggestions. Offline, the app's last loaded list
is read-only and actions wait for the service.

## Composing

A private composer has separate **Suggestions** and **Send** buttons. A blank
draft requests messages to continue the conversation; a nonblank draft is the
starting idea, which every option develops into a complete message, and text
in square brackets instructs the writer without appearing in any option.
Generation keeps the draft editable and sends nothing. Choosing a manual
option replaces the draft's text, keeping photos, a GIF and the reply target,
with the caret at its end; an automatic option is inserted at the caret.
**Undo suggestion** restores the prior draft. Suggestions is disabled with its
spinner while any set for the chat is being prepared, and without it while
one waits for budget, AI processing or the provider; a draft edit that
withdraws a manual set frees it. Send asks first while the draft still has
[bracketed] text. The per-chat Style applies to manual and automatic sets.
Groups and Saved Messages have no Suggestions button. Return inserts a
newline. A long press offers Reply and
Copy; in AI reading, Reply answers the block's latest source.
Swiping a message from right to left past a threshold shows a reply arrow with
a light vibration and replies the same way, wherever the sheet offers Reply;
it is off during selection and on pending sends. Every reply shows a Reply
Quote of the message it answers ([ADR 41](adr/0041-reply-quotes.md)); tapping
it scrolls to that message, loading earlier pages until it is shown, and
outlines it briefly. The sheet also offers Copy transcript for voice and video
messages and Share for photos, voice notes, video messages, videos, documents
and music files ([Media](#media)), and in a private chat a row of reactions
([Message details](#message-details)).

A pending send looks like a sent message: its state is an icon in the time
line, a clock while sending that turns into the tick once sent. Not sent and
Delivery unknown add a red "!" and their word, Send held keeps the clock with
"Held", and Cancelled stays dimmed. A long press, or a tap on the "!", opens a
sheet with exactly the actions the service allows: Retry, Check delivery,
Cancel send, Review for a paused group send, and Copy.

The draft lives on the service; what is typed stays in the app's cache folder
until the service holds it, and comes back after a restart with "Unsaved
draft restored on this phone." Nothing is queued while the server can't be
reached: Send then keeps the draft and says so, and a second Send of the same
draft returns the first send rather than a new one.

The paperclip offers Photo library, Take photo, GIFs and Stickers. It
attaches up to ten photos from the library or one taken with the camera. Each
is re-encoded as a JPEG with its longest side at most 4,096 px and at falling
quality until it fits 5 MB, the service's photo bounds; this also turns HEIC
photos into a type the service accepts and drops their location and camera
details. Taking a photo asks for camera access once, and a refusal is shown
with where to change it. The library opens the system picker, which needs no
photo access permission.

## Media

Received media play in the app as in the web; the service side is in
[media delivery](media-delivery.md#playback-in-both-clients). Voice notes share
one audio player with Telegram's waveform, tap or drag to seek, the speed
button (1×, 1.5×, 2×, kept in the app's documents folder) and the next voice
note playing on. They keep playing with the screen locked or another app open,
with lock screen controls, until the chat closes or the reading view changes;
iPhones play the service's AAC copy. Show transcript shows a note's raw
transcript, the owner's own notes included, and starts one when it is missing.
Video messages play in their circle and pause a voice note.

Tapping a photo or video opens the **Media Carousel**: every photo and video
the chat has loaded, in date order, at the tapped one, with swipes between
them, pinch and double-tap zoom, a counter, Share and a swipe down to close. A
video prepares there (up to 50 MiB) and plays with the system's controls and
full screen. Telegram albums show as one grid that opens the carousel at the
tapped item. GIFs loop silently while their row is on screen and the chat is
in front, static stickers are images, TGS stickers play through Lottie and
video stickers show their still image; reduce motion stops them. Share saves
the file beside the offline copy, where forgetting the phone deletes it, and
hands it to the system's share sheet. Holding a play button, a photo or a
file card opens the message's sheet, as holding the message does.

The players are native modules: expo-audio (its config plugin turns on
background playback and its Android media service, and asks for no
microphone), expo-video, expo-image and lottie-react-native. The swipe, zoom
and carousel use React Native's own PanResponder, Animated and Vibration. The
reminder editor's date and time pickers are
`@react-native-community/datetimepicker`, the version Expo SDK 57 bundles
(9.1.0): Android's own dialogs, iOS's wheels in a sheet with Done. Adding a
native module means rebuilding Enloq Dev and a new Saved Build; JavaScript
changes need neither.

## Message details

Messages from one sender form Message Runs, broken by another sender, a date
line, the Unread line or a gap of more than five minutes: smaller gaps inside
and a tail on the run's last bubble. Private chats show no names or avatars.
Reaction chips sit under a message: ⭐ for a paid reaction, ◇ for a custom
emoji, the count above one and the owner's own outlined; they aren't
tappable. In a private chat the long-press sheet opens with a reaction row:
the owner's own first, six from the account's palette
(`GET /api/accounts/{id}/reactions/options`) and + for the rest. Choosing the
owner's own removes it, and an AI block with several messages asks which one.
Groups show chips only. Forwarded and imported messages carry their line
("Forwarded from …", the original date and time); the app reads a loaded
message's missing header in batches of 100, at most once a minute each. An
edited message shows a pencil, and in Originals, with versions captured,
Previous, "2/3" and Next step through them: an earlier version shows its text
and its photo while cached, and its sheet offers only Copy. A deleted message
keeps what it last said, with a trash icon, until the owner hides it for good
with the sheet's Hide or a selection
([ADR 52](adr/0052-deleted-messages-hiding-and-the-header-ai-toggle.md)).
Polls, venues, contacts and link previews are cards. The service keeps no
phone, coordinates or preview text, so a contact shows its name, a venue opens
the maps app's search for it and a preview opens the message's link. Away
from the latest message, Scroll to latest brings it back.

## AI controls and the profile

A private chat's header ends with the Reading View's robot, pressed for AI
reading. In AI reading, a block that is text only shows its originals
together in one bubble headed "N messages · time", without "AI ·" or a status
([ADR 54](adr/0054-incoming-text-combined-not-rewritten.md)); a softened block's
head ends with "Softened"
([ADR 53](adr/0053-calming-hostile-messages-and-removing-adaptive-tone.md)); a
block with an image, a voice note or a video circle shows its rewrite. A block
without AI text that failed or stopped shows Retry beside its status and in
its long-press sheet, off while the account's AI processing is off. A
rewritten block's sheet offers Show original, and its originals' sheets Show
AI text: the choice holds for that block alone until the header's robot
changes. Under a finished block, "Not analysed: …" names what the AI skipped.
At the top of the loaded history "N earlier blocks are not rewritten" offers
Rewrite for blocks with an image, a voice note or a video circle; a run shows
"Analyzing earlier messages · n of m" with a bar and Stop, and afterwards how
many remain and why. A private chat's header says AI off while the account's
processing is off.

The header shows the emotion's emoji right after the name, which gives way
first. Tapping the photo, name or emoji opens the **Correspondent Profile**:
the person's photo, name, @username, phone number when Telegram shares it and
bio, which the service reads from Telegram on each opening and never stores;
the emotion with its reason, source and time; **Soften hostile messages**, On
by default, for hostile wording independently of anger or frustration;
**Automatic suggestions**, On by default; and **Style**, Friendly by default,
with Friendly, Professional and Idioms choices for both generation kinds
([ADR 56](adr/0056-idioms-either-signal-hiding-and-memory-off-by-default.md));
**Remember this chat**, off by default; **Cares about**, the chat's Person
Memory; **Traits**; and Copy chat link
([ADR 55](adr/0055-person-and-account-memory-and-traits.md)). Cares about lists
the entries with their source and adds, edits, removes and clears them, with
Retry after a failed update. An entry holds 300 bytes, so the field counts
bytes: letters outside English count two. Traits show counted habits, scales
with their confidence and notes; the owner sets or clears any scale, which the
model then never changes, and adds, edits or removes notes. **About you**, from
Manage accounts, shows the same for the account's holder: You care about and
Your traits. Offline the profile shows the cached chat's photo, name and
emotion and says the rest needs the server.

Tapping a group's photo and name opens the **Group Profile**: the group's
photo and title, its @username when public, its member count and description,
read from Telegram on each opening and never stored (`…/group-profile`,
`channels.GetFullChannel` or `messages.GetFullChat`), with no member list,
then Copy chat link. A group that lost access, or a phone offline, shows the
cached photo and title with the reason. Group AI processing and Hide bots stay
in the group's ⋮ sheet. A group member's avatar or name opens their profile:
photo, name, @username and bio, read on opening, with **Message**, which opens
the private chat with them as New Message does.

## Selection and deletion

Both clients delete originals for both participants, or in a group the
owner's own originals for everyone. In Originals, an eligible original's
long-press sheet offers Select. Round checkboxes then sit beside the originals
that can go, a tap on a row adds or removes it, and a bar with "N selected",
Delete and Cancel takes the composer's place; the composer keeps its draft.
Delete opens a review of the account, the chat and exactly the messages
chosen, read afresh from the service; a message edited meanwhile asks for
another review. Delete for both participants (Delete for everyone in a group)
hands the deletion to the service, which owns it from then on: the selection
ends, the messages say Deleting…, and a card under the latest message follows
its progress, with Check result and, after a fresh review, Retry remaining.
When the answer is lost the card says Submission unconfirmed, with Check
submission and, until the app closes, Review submission, which sends the same
reviewed intent again; only its identity is kept across a restart. Selecting
deleted messages offers Hide instead. Android's Back, Cancel, the AI view and
leaving the chat end a selection.

## GIFs and stickers

GIFs shows the account's saved GIFs, and a search through the configured bot
runs once typing pauses, with More for the next page. Stickers shows recent
and favorite stickers and each installed pack, narrowed by a local filter on
names, emoji and keywords. Tiles are still images; one the account can't send
says why, such as Telegram Premium. A tile stages its GIF or sticker above
the composer while the service prepares it, with Retry if that fails and a
button to remove it; the staging survives restarts. Send sends a GIF with the
text as its caption. A sticker sends on its own: the text field steps aside,
Generation, Undo and suggestion insertion wait, and the text stays as Draft kept. Video
stickers show still on the phones.

## Groups

Groups shows the account's Group Chats active in the last seven days
([ADR 34](adr/0034-group-chats-and-daily-briefings.md),
[ADR 42](adr/0042-groups-and-briefings-in-the-enloq-app.md)); a `chat:` or
`channel:` link opens the group screen. Group reading's pure rules are the
web's, in `shared/groupBriefings.ts`. Each day reads under its green date band,
and the band of the day at the top stays pinned over the list. In AI reading
a briefed day shows its Daily Briefing card, and what the briefing does not
cover yet folds under **N new messages**; folded messages are not counted as
viewed until the fold is opened. Originals show every original, other
people's runs with their name in one of Telegram's seven colours on the first
bubble and their avatar beside the last, a signature and `(ad)`. Groups show
Sent but never Read.

Today's band carries the **Briefing Slot** in AI reading: `↻ N new` or
`↻ Update` and the amber Retry act on a tap, paid from the Group Briefing
Budget; Waiting, Budget, Syncing and the check only report, and nothing can
be tapped while the server can't be reached. A citation (`#12`) or **Show day
originals** swaps the day's card for its cached originals in place, the cited
one outlined, and **Return to briefing** at the top of the day brings the card
back. A Reply Quote to a summarized, folded or hidden message reveals it the
same way. The header's ⋮ opens **Group AI processing**, with why it can't
brief, and **Hide bots**; a passive AI off tag shows while account or group
AI is Off. A bot original that Hide bots hides offers **Stop ignoring this
bot** in its long-press menu once it shows.

The composer offers Send without suggestion generation, and acts only while
the group's native access is verified. Offline, the Groups list and
opened groups stay readable, while the slot, the switches and sends wait for
the server.

### Group recovery

Both clients reach group work the seven-day Groups list no longer shows. A
folded Retained group work at the foot of Groups lists each group that still
holds a saved draft, an unresolved send or deletion, with a line saying
which; a group opens read-only with its cached history, and its saved draft
can be copied. A send proven unsent after the group's access was lost says
Not sent with Review and resume. Review asks the service to check the rights
again and shows exactly what would go: the account and group, the reply,
images, GIF or sticker, and text. Resume sends it within the review's two
minutes; once they pass, the review closes and must be opened again.

## Saved Messages

**Saved**, the switch's third tab, shows the account's own Saved Messages in
place of a list ([ADR 50](adr/0050-icon-tabs-saved-messages-and-one-saved-build.md)):
its timeline, newest at the bottom, Load earlier and the composer without
suggestion generation or Undo. The message menu offers Copy, Reply, Select
and the media actions, but no reactions, which Telegram treats as its Premium tags
there. Nothing in it goes to a model, is unseen or alerts, and its content
follows the chats' 30-day rule. Every account has its own, members' included.

## Notifications (Android)

**Settings → Notifications** turns this phone's notifications on or off,
chooses sound and sends a test notification. The list asks once per pairing,
while this phone's notifications are off and the server sends them: Android 13
and later shows Android's own dialog at once, and Android 12 and older (the
S9+) a **Turn on notifications?** sheet with Turn on and Not now, so Google is
contacted only on a yes. The ask belongs to the phone's trusted entry, so
pairing again asks again; declining leaves Settings → Notifications. iOS asks
nothing until it has push. Pushes travel through Firebase Cloud Messaging, so
the phone needs only Google Play. Enloq first contacts Google when
notifications are turned on; turning them off, being forgotten or pairing
again deletes its FCM token.

Each push is a data message carrying only an event
([ADR 20](adr/0020-minimal-reading-and-ready-notifications.md)). Through
`expo-notifications`, it runs the app's push task (`mobile/src/pushTask.ts`,
loaded by `mobile/index.ts` before the router), even when the app was closed.
The task asks the server for the sender and preview with the phone's stored
credential and shows them on the **Messages** channel (**Messages without
sound** while sound is off), replacing the chat's older notice; if the server
can't answer within a few seconds, a generic notice opens the app. Tapping a
notice opens its chat. While the phone shows a chat, it tells the server, so
no destination alerts for that chat. A force-stopped app receives nothing
until it is opened again.

Builds read Firebase's config from the ignored `mobile/google-services.json`
(mode 600, never committed or printed), one copy in each checkout that builds
Android; a build without it has no push. The iPhone gets no push until Apple
Developer enrollment, and its builds leave out the push entitlement that free
signing rejects (`mobile/app.config.ts`).

## Settings

**Settings**, the account sheet's last row, opens the same menu on both
platforms ([ADR 45](adr/0045-settings-in-the-enloq-app.md),
[ADR 47](adr/0047-pairing-settings-menus-and-profiles.md)). Every setting but
this phone's notifications is service-wide: each account and trusted client
shares it, and the web's Settings changes the same values. Each row has its
icon and what it holds on the right, and opens a page of its own:

- **Notifications** (a bell; Android only, see above; On or Off).
- **Budget** (a wallet; today's Daily Budget spending): a card per budget
  with a meter of today's counted spending, "$… of $… today · N calls", the
  reset in the service's calendar, or the reached warning, **Change limit**
  ($0 to $10 in whole cents; $0 notes that new work stops) and **Recent
  changes**.
- **AI** (a chip; **Paused** while a role is paused): **Minimum characters**
  (the Processing Character Threshold, 0 to 10,000, which governs group
  briefings), **Model calls at once** (1 to 8), the **Memory** and
  **Automatic suggestions** switches, and **Guidance** (Processing Guidance), which
  names its version. While the decision model is unavailable, a notice above
  them says since when.
- **Privacy** (a lock; the trusted count): **Pair a phone**
  ([above](#pairing)), then **Trusted browsers and devices**.
- **People** (two people, the owner's only; "N waiting" while Join Requests
  wait, then the member count): requests with Approve and Decline, and members
  with their accounts, last activity and today's spending against each budget,
  **Edit budgets** and **Remove** after a confirmation. A join request's
  notification opens it.
- **Disconnect from <server>** and the build line at the foot.

A member ([ADR 48](adr/0048-members-on-the-shared-service.md)) sees no AI row
and no People: Budget shows their own budgets read-only, with "The server's
owner sets your budgets.", and **Leave Enloq** above Disconnect signs the
server out of their Telegram accounts, deletes everything it keeps for them
and returns to pairing. A changed Member Agreement covers the app until they
accept it.

Switches and the stepper apply at once; amounts and text apply with Save.
Every write is followed by a fresh read, and another client's change rereads
Settings without losing an unsaved edit. A refusal shows under its control.
Nothing is kept offline: while the server can't be reached, the last values
stay shown and can't be changed.

Guidance groups its 14 fields as Rewriting, Tones and Other work, each marked
Edited or Default over its first line. A field's editor has Save, **Reset to
default** after a confirmation and the default text; leaving with unsaved text
asks first (iOS's swipe back is off meanwhile). A role paused after three
format failures shows a notice with **Keep** and **Reset guidance**, which
restores that role's fields.

"Waiting for budget" in a chat and "Suggestions wait for budget" by the
composer open the Daily Budget, "Paused after repeated format failures" opens
Guidance, and a group's Budget in today's band opens the Group Briefing
Budget; the Budget page scrolls there and outlines it briefly.

## Using Enloq

The app has no Help screen; this is what a Help screen would explain.

- **Reading.** The robot in a chat's header switches between AI and Originals
  reading for every chat. In AI reading, text arrives as it was sent, grouped
  into one bubble per block; hostile wording is softened while Soften hostile messages is On and is marked
  Softened. Anger or frustration alone is left as sent. A block with an image, a voice note or
  a video message is rewritten as readable text. The originals keep the exact
  messages and order. The Unread messages line marks where unseen messages begin when a
  chat opens; it is Enloq's own marker and doesn't change what Telegram shows
  as read.
- **Voice and video messages** become clear written text without fillers. A
  word, name or number the recognizer may have misheard is followed by (?);
  Show transcript shows what was recognized, your own notes included, and
  Copy transcript in the message's sheet copies it. Voice notes play on into
  the next one at the speed you last chose on this phone, also with the screen
  locked, until you leave the chat or switch the reading view.
- **Reactions**: hold a message in a private chat and pick an emoji at the
  top of its sheet; picking your own again removes it. + shows the rest of
  your account's emoji.
- **Versions**: an edited message shows a pencil; in Originals its arrows step
  through the earlier wordings Enloq captured in the last 30 days. A deleted
  message keeps its last words with a trash icon until you hide it.
- **The header emoji** estimates the emotion in the latest incoming block; 😐
  also stands in while that is uncertain, pending, changed or older than 12
  hours.
- **Suggestions**: automatic sets appear for a current emotional or useful
  incoming block; reactions still need both signals. **Suggestions** works
  with automation Off and after your own message or an ended exchange; your
  draft is the idea its complete messages develop, and [bracketed] text tells
  the writer what to do. A current manual set stays until replaced or
  withdrawn by a draft/source change or its 12-hour request-time expiry.
  Style changes apply to the next generation, without starting work. A manual
  choice replaces the draft, an automatic one is inserted, Undo restores, and
  Send remains separate.
- **Writing.** Write, attach or reply, then press Send. Generating
  suggestions never changes or sends the draft; only choosing one replaces
  it, with Undo. Send asks first while [bracketed] text remains. Outgoing
  Rewrite and its tone controls are removed.
- **Groups** list basic groups and supergroups active in the last seven days.
  Group AI processing starts Off; turn it on in the group's ⋮. Groups offer
  Send without suggestion generation, and send no sound or push.
- **Budgets.** The Daily Budget pays private-chat processing, suggestions and
  arrival screening; the Group Briefing Budget pays briefings and their Retry.
  Each is shared by all your accounts and never changes by itself. Counted spending
  is the provider's receipts plus a flat estimate for each unknown cost. New
  calls wait at the limit, and started calls may finish slightly past it.
- **Processing.** Minimum characters applies to group briefings: a day starts
  once its messages reach that many characters, and images, voice notes and
  videos don't need it. Model calls at once limits all accounts together;
  private work precedes briefings, which precede idle memory. Transcription
  runs one at a time. The Memory switch
  stops use and updates without deleting anything. Guidance applies from the
  next model call; work already started keeps its version, and group
  briefing guidance is separate from the private-chat fields.

## Checks

`./scripts/check` runs the app's typecheck, Prettier and Jest suites after the
backend and web checks; they need only `npm --prefix mobile ci`, not Xcode or
the Android SDK. `./scripts/schema` writes the app's API types beside the
web's, from the same `config/api-schema.json`. Work is checked with
`./scripts/check` and on the Android phone; the iOS simulator journeys run on
the Mac when the iPhone build is made there.

For a journey on a simulator, emulator or phone, start the authored fixture
server and pair with it:

```sh
uv run --locked python scripts/test_server.py   # port 8776, authored data only
uv run --locked python scripts/fixture_pair.py   # prints a link, approves the claim
```

The app accepts `http://127.0.0.1:8776` links only for that local fixture. An
Android device reaches it after `adb reverse tcp:8776 tcp:8776`. Never point
the helper at a personal or VPS service: it approves the first claim.

### Journeys

The Maestro flows in `mobile/maestro/` (`journeys.yaml` runs
`mobile/maestro/flows/` in order) walk the app on the booted simulator (Enloq)
or the connected phone (Enloq Dev) against that fixture only: pairing by
pasted link, with the notification ask that follows it dismissed on Android;
both reading views; a Reply with Suggestions, a replacing choice, Undo and
Send whose quote shows in the composer and after sending; a group with its
Group Profile, Group AI processing, Update briefing through the fixture's fake
engine, a citation and Return to briefing, a Reply and today's new-messages
spoiler; Saved; on Android, reminders (the tab's rows, a pending reminder's
chat with its Reminder Bar, set, Undo and Dismiss, the editor's Repeat, day
grid and native time picker, and Remove's question); Settings
through its menu to Budget, AI, Guidance and Privacy's Pair a phone QR code;
media (a voice note's speed, a video message taking over, Copy transcript and
Share from the sheet, a video, a GIF and stickers); the Media Carousel; New
Message; message details (versions, forwarded and imported lines, cards,
Scroll to latest and reactions); AI controls; deletion; GIF and sticker
sending; group recovery; and account switching. Android also runs response
suggestions, notifications (turned on, which registers Enloq Dev with FCM, a
test through the fixture's fake sender, then off), pairing again by the local
test server and by a code that submits itself, Manage accounts with a login by
the fixture's synthetic code, People (a seeded Join Request approved, its
budgets changed and the member removed) and joining (a stranger's sign-in, the
Member Agreement, the waiting screen until the fixture approves, a member's
Settings and Leave Enloq, then the owner paired again). The suggestions flow
waits for the next iPhone build on the Mac. Each run sets the fixture's
authored groups up afresh, AI Off and unbriefed, and its authored media chats
with `scripts/fixture_seed.py`. Install the development build first, then:

```sh
mobile/scripts/journeys ios
mobile/scripts/journeys android
# Pair afresh and run just the reminder checks:
mobile/scripts/journeys android maestro/reminders.yaml
```

The script starts the fixture server and Metro when they aren't running and
stops what it started; its Metro points Enloq Dev's Connect at the fixture,
never the release server. It resets the app's pairing (the simulator's
keychain, or Enloq Dev's data on Android), supplies a fresh pairing link that
the helper approves, and runs Maestro with its analytics off. Logs,
screenshots and a JUnit report land in `.local/journeys/`. On Android it takes
over the phone's screen for a few minutes; the Enloq release app is never
opened. Maestro (2.6 or later, with JDK 17) is installed outside the
repository.

Development builds skip the developer menu's introduction, its menu at launch
and its floating button (`mobile/app.config.ts`), so every launch starts on the
app's own screen. Open the menu with a shake, Ctrl-D on the simulator or
`adb shell input keyevent 82`.
